# KonadoScript

KonadoScript는 비주얼 노벨에 맞춰 설계된 창작 언어입니다(파일 확장자는 `.ks`).

더 강력하고 구조화된 "소설 대본"이라고 생각할 수 있습니다. 개발자는 복잡한 코드를 작성하지 않고도 이야기 대화, 캐릭터 스탠딩 이미지, 배경 전환, 음악과 효과음, 이야기 분기와 선택지를 제어할 수 있습니다.

## 설계 철학

KonadoScript의 핵심 설계 철학은 **이야기 내용**과 **프로그램 로직**을 분리하는 것입니다.
- 작가는 프로그래밍 지식 없이 서사 내용에 집중할 수 있습니다
- 프로그래머는 이야기 창작에 개입하지 않고 엔진 개발에 집중할 수 있습니다
- 리소스 관리(이미지, 오디오)는 식별자를 통해 참조하며 스크립트와 분리됩니다
- 모듈식 명령 집합으로 새 기능을 쉽게 확장할 수 있습니다
- Git 등 버전 관리 시스템과 호환됩니다
- 텍스트 형식은 본질적으로 크로스 플랫폼입니다
- 리소스 참조는 플랫폼에 의존하지 않습니다

## 자주 묻는 질문

### 1. 파싱 오류 처리

Godot 스크립트 편집기는 입력하는 동안 KonadoScript의 구문 및 의미 문제를 표시합니다. 잘못된 내용도 `.ks` 원본 파일에는 저장할 수 있지만 현재 런타임 `KonadoShot`은 갱신되지 않습니다. 오류를 수정하고 다시 저장하면 리소스 로더가 자동으로 컴파일하므로 수동으로 다시 가져올 필요가 없습니다.

### 2. 스크립트 파일 인코딩 문제

스크립트 파일이 UTF-8로 인코딩되어 있는지 확인하세요. 그렇지 않으면 글자가 깨질 수 있습니다. 기본적으로 생성되는 스크립트 파일의 인코딩은 UTF-8입니다.

### 3. 내보낸 빌드의 스크립트 보호

프로젝트를 내보낼 때 Konado는 현재 내보내기 프리셋의 `Konado -> Script Encryption Key` 값을 읽어 컴파일된 `.ks` 스토리 데이터를 자동으로 암호화합니다. 키가 비어 있거나 형식이 올바르지 않으면 임의의 256비트 키를 생성하여 해당 빌드에 사용합니다. 이후 내보내기에서는 개발자가 직접 변경하지 않는 한 이 키를 다시 사용합니다.

패치 또는 핫 업데이트를 배포할 때는 기본 빌드와 업데이트에 같은 내보내기 프리셋과 키를 사용해야 합니다. 키는 `.godot/konado_export_credentials.cfg`에 저장되므로 장기간 사용해야 한다면 별도로 백업하세요.

로컬에서 내보내면 Godot 터미널에 전체 빌드 키가 출력되어 개발자가 기록하거나 문제를 진단할 수 있습니다. 이 기능은 일반적인 추출 도구로 PCK에서 스토리 원문을 직접 읽는 것을 방지하기 위한 것으로 전용 DRM을 대체하지 않습니다. 내보낸 리소스, 클라이언트 코드 또는 런타임 메모리를 표적으로 분석할 수 있는 공격자는 여전히 스토리 내용을 복원할 수 있습니다.
